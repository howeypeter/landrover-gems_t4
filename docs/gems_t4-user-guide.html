gems_t4 User Guide

How to install and use gems_t4 — the GUI and the command line. What each feature does (read fault codes, live data, actuator tests, coding, immobiliser), and how to point it at your vehicle. No soldering or electronics knowledge needed — for that side, and for how any of it works under the hood, see the Field Manual.

P38 4.0/4.6 · Disco 1 V8i Windows · Python GUI + CLI practice emulator built in v0.0.10

01Welcome

gems_t4 is a software recreation of the Land Rover dealer diagnostic tool (the TestBook T4), for the GEMS V8 engine ECU fitted to the P38 Range Rover 4.0/4.6 and the Discovery 1 V8i (1995–early 1999). It talks to the engine ECU the way the dealer tool did: read fault codes, watch live engine data on period-style gauges, run actuator tests, and read/write the small coding settings.

Two ways to run it:

  • GUI — a full-screen, touch-friendly kiosk styled after the original dealer tool. Best for guided, click-through use.
  • CLI — the same features from the command line. Best for quick reads, scripting, and the bench.
✓

Practise on the built-in emulator before you touch the car

gems_t4's job is to diagnose a real GEMS ECU — fault codes, live data, actuator tests, coding — over a small USB or Bluetooth adapter (§06). It also ships with a built-in emulator (a virtual ECU that behaves like a real engine, with four fault scenarios), so you can install it and learn the whole workflow first with nothing plugged in. Practise on the emulator, then point the same screens at your vehicle.

02Install & first run

You need a Windows laptop with Python 3.11 or newer (developed on 3.14). Open PowerShell in the project folder and run:

python -m venv .venvcreate an isolated environment
.venv\Scripts\Activate.ps1activate it (PowerShell)
pip install -e ".[gui]"install with the GUI

Want the command line only, without the large GUI dependency? Use pip install -r requirements.txt instead — then everything except gems_t4 gui works.

Quick smoke test (no hardware): python -m gems_t4 scenarios should list four fault scenarios. If it does, you're installed.

Launching the GUI

  • Double-click launch_gui.bat (Windows), or run python -m gems_t4 gui.
  • create_shortcut.ps1 puts a desktop shortcut in place if you'd like one.
  • Add --instant (gems_t4 gui --instant) to skip the period-authentic “communicating with ECU… please wait” pauses while you're testing.
i

The launcher runs the live code, not a frozen copy

launch_gui.bat runs straight from your installed source, so it always reflects the current version — there's nothing to “rebuild.” After a git pull you're up to date. The version (e.g. gems_t4 v0.0.10) is shown on the boot splash and in the window title.

03The GUI, screen by screen

The GUI is guided, like the real dealer tool: you identify the vehicle, then pick a function from a menu. Big buttons, a tick / cross / back bar, and a persistent “VCI:” connection indicator in the title bar that you can click to jump to connection settings.

ScreenWhat you do there
Boot splashPeriod-style start-up; shows the version and “RDS 5.06 / T4 Lite.”
Vehicle IDIdentify the vehicle (the classic “GEMS or Thor?” fork). On the emulator, this is also where you pick which fault scenario to practise with.
System menuThe hub — choose Fault codes, Live data, Actuator tests, Programming, Toolbox, or Configuration.
Fault codesRead stored trouble codes, and clear them (with a confirmation prompt). Clearing wipes all codes — GEMS has no per-code clear.
Live dataA grid of analog gauges showing live engine values. Selecting more gauges visibly slows the refresh — that's the real K-line speed, modelled honestly.
Actuator testsCommand an output (MIL lamp, O2 heater, fuel-pump relay, A/C, condenser fan) and watch the tool's safety refusals when a test isn't allowed.
ProgrammingA sub-menu: Coding (read/edit/write settings), Immobiliser (Security-Learn), and Maps (a read-only fuel/ignition viewer).
ToolboxSelf-tests (LAN-card check with the original dealer disclaimer, VCI check, touchscreen calibration) and an About screen.
ConfigurationChoose the connection: Virtual ECU, USB COM port, or Network — test it, and save it for next time.

04Features at a glance

The same functions are available in the GUI and the CLI. Here's what each one actually does:

FeatureWhat it does
Read fault codesReads stored (and pending) diagnostic trouble codes — e.g. P0118, P0303, P1185 — with plain descriptions.
Clear codesErases all stored codes after you confirm. This is a normal, safe service action.
Live data40 live measures: coolant/oil/intake temps, RPM, air-flow, throttle, battery, O2 sensors, fuel trims, injector pulse width, coil charge, per-cylinder misfire counts, and more. Watch a few for a fast refresh, or many for the full picture at a slower rate.
Actuator testsBriefly drives an output to check it: MIL lamp, O2 sensor heater, fuel-pump relay, A/C clutch, condenser fan. Tests that would be unsafe are refused — e.g. the fuel pump won't run with the engine running.
CodingRead, edit, and write the ECU's small settings: VIN last-6, dealer ID, 4.0/4.6 select, transmission, build code. Writes are gated: back up → write → read back to verify → you confirm. Some fields are read-only.
ImmobiliserCheck immobiliser status and run the Security-Learn re-sync — the procedure that recovers an “ENGINE IMMOBILISED” no-start. This one needs the vehicle (see §06 / §07).
MapsA read-only 16×16 fuel/ignition table viewer plus the EPROM chip facts. There's deliberately no write path — GEMS tunes live on physical chips, not something you change over the cable.
Toolbox / AboutThe dealer-tool self-tests and version info, reproduced for authenticity.

Four fault scenarios ship with the emulator — healthy, coolant_sensor, misfire_cyl3, and lambda_heater. Each one shows up consistently across every screen: the same fault appears in the codes, in the live data, and in the actuator refusals. They're the best way to learn the read → diagnose → clear workflow.

05The CLI

Run any command as python -m gems_t4 <command>, or just gems_t4 <command> once installed. Add -h to any command for its options. By default everything runs against the emulator; add --scenario NAME to pick a fault.

CommandWhat it does
gems_t4 scenarioslist the four fault scenarios
gems_t4 liveread live data (add --scenario coolant_sensor)
gems_t4 dtc readread fault codes
gems_t4 dtc clearclear codes (prompts to confirm; --yes to skip)
gems_t4 actuator fuel_pumprun an actuator test (shows the engine-running refusal)
gems_t4 coding readshow the coding block (coding write to edit, gated)
gems_t4 immo statusimmobiliser status (immo learn for Security-Learn)
gems_t4 guilaunch the GUI (--instant skips the waits)
gems_t4 serveshare an ECU over the network (see §06)
gems_t4 kline dtc --port COM5talk to a real ECU (see §06)
✓

Try this first

gems_t4 dtc read --scenario misfire_cyl3 then gems_t4 live --scenario misfire_cyl3 — you'll see the same cylinder-3 misfire reflected in both the codes and the live data. That consistency is the whole point of the emulator.

06Connecting to a real ECU

To talk to a real GEMS ECU you need the small K-line adapter (a Raspberry Pi Pico + one transceiver chip — building it is covered in the Field Manual). Once you have one, gems_t4 reaches the ECU three ways:

ConnectionHowNotes
Virtualdefaultthe built-in emulator — no hardware
USB--port COMxthe Pico adapter on a USB serial port
Bluetooth (BLE)--blea wireless Pico — no pairing, no COM port; needs pip install bleak
Network--connect HOST[:PORT]a shared ECU over your network (via gems_t4 serve)

The real-ECU commands live under gems_t4 kline:

gems_t4 kline dtc --port COM5read fault codes from a real ECU on USB
gems_t4 kline live --blelive data over Bluetooth
gems_t4 kline monitor --blea continuous live monitor
gems_t4 kline clear --port COM5clear stored codes

In the GUI, choose the connection on System menu → Configuration, test it, and save it — the “VCI:” indicator then shows the live link on every screen.

i

Network links are read-only by default

Over a network connection, write actions (coding, actuator tests, Security-Learn) are refused unless you deliberately add --allow-writes on a link you trust. Reading and clearing codes stay allowed. Keep serve on your own machine or an SSH tunnel.

⚠

Immobiliser Security-Learn needs the car

The Security-Learn re-sync pairs the engine ECU with the vehicle's body computer (the BeCM). It only works with that module present and powered — i.e. in the vehicle, not on a bench. On a real ECU this is still being validated; treat it as advanced. The everyday reads (codes, live data) are safe and well-proven.

07Safety & limits

A quick, honest picture of what's safe and what to expect:

  • Reading is safe. Fault codes, live data, and coding reads don't change anything on the ECU.
  • Clearing codes is safe and normal — it just resets stored faults.
  • Writes are gated. Coding writes back up the block, write, then read back to verify, and ask you to confirm. On a real ECU, write features (coding, Security-Learn) are newer and less proven than reads — go carefully.
  • You cannot re-tune a GEMS over the cable. The fuel/ignition maps live on physical chips; no dealer tool ever reflashed them over the diagnostic port, and neither does this one. The Maps screen is a viewer.
  • The emulator is always safe — experiment freely; nothing you do there touches a vehicle.

08Troubleshooting & FAQ

SymptomFix
gems_t4 gui won't start / “No module named PySide6”Install the GUI extra: pip install -e ".[gui]". The plain requirements.txt install is CLI-only by design.
The gems_t4 command isn't foundActivate the venv (.venv\Scripts\Activate.ps1), or use python -m gems_t4 …. Make sure you installed from this project folder, not a downloaded ZIP.
Real ECU: nothing responds on USBCheck the COM port number (Device Manager), that the adapter is powered, and that the ignition is on. Confirm with the emulator first to rule out the software.
Real ECU: Bluetooth not foundRun pip install bleak, make sure the wireless Pico is powered and advertising as gems-pico, then retry --ble.
The GUI feels slowThat's intentional — the “communicating with ECU” pauses are period-authentic. Use gems_t4 gui --instant to remove them.
“Read VIN” returns nothing on my ECUNormal on a Discovery 1 — the full VIN lives in the alarm module (10AS), not the engine ECU. The engine ECU doesn't hold it.
